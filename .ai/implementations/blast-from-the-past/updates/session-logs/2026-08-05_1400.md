# Session - 2026-08-05 14:00

## Goal

Add a third, clearly separate game-oriented dam-break column to the studio so
the interactive approximation can be evaluated beside scientific Adaptive and
Uniform WCSPH.

## Planning checkpoint

Boot sequence completed. The proposed design uses an isolated GPU Position-
Based Fluids solver with fixed particles, bounded iterations, an approximate
impulse-coupled floating box, and explicit solver/render timing. ADR-0012 and
Tier-2 plan `2026-08-05_warp-gameplay-pbf-dam-break-column` are awaiting owner
approval. No implementation code has been changed.

## Approval

@kunalpuri-prediqt approved the Tier-2 plan at
2026-08-05T14:01:32 CEST with the verbatim response:

> approved

Implementation inspection found that `UniformGridWarpNNPS.update(push=False)`
still calls `.get()` on device positions to recompute bounds. The isolated
gameplay solver will therefore use Warp's device-built `HashGrid`, preserving
the approved fixed-resolution GPU-neighbor intent without a hot-path host
readback or any scientific NNPS change.

## Implementation

- Added isolated `pysph/base/warp_game.py`. It keeps fixed fluid state on the
  Warp device, builds a device `HashGrid`, performs three PBF density
  projections per `1/60 s` step, reconstructs velocity, and applies an
  explicit XSPH smoothing pass.
- Added analytic tank projection plus a quaternion rigid box with bounded
  linear/angular correction impulses, angular-speed limiting, damping, and
  transformed shell rendering. It is deliberately not Liu/WCSPH coupling.
- Guarded maximum applied projection travel against the neighbor skin and
  exposed density constraint, frame time, correction limiting, body state,
  runtime, and approximation telemetry.
- Routed `solver_family=gameplay-pbf` through the existing spawned worker and
  added `Gameplay · fast` to the studio. Pressure coloring falls back to speed;
  Adaptive remains the default and both scientific paths are unchanged.
- Added gameplay controls for timestep, substeps, projection iterations,
  velocity retention, and XSPH smoothing. Result NPZ/manifest schemas remain
  self-describing and compatible with the studio loader.

## Tuning and benchmark

The correction-cap sweep selected `0.20 dx` over `0.25/0.30 dx`: it produced
the lowest frame-130 density-constraint RMS and a less energetic rigid-body
response while leaving `0.40 dx` unused neighbor skin over three projections.
Linear/angular impulse caps and a `12 rad/s` spin cap fixed the unbounded
prototype body response.

Final RTX 5090 benchmark, 1,000 fluid particles, 120 measured frames after 10
warm-up frames:

- solver median/p95: `1.049/1.244 ms`;
- snapshot/readback median/p95: `0.662/0.830 ms`;
- solver-plus-snapshot loop: `574.7 FPS`, excluding transport/browser render;
- compile and initialize: `97.189 ms`;
- all finite, rigid device error zero, shell drift zero.

The separate 240-frame/four-second run remains finite with density-constraint
RMS `0.07284`, body angular speed `1.167 rad/s`, and solver median/p95
`0.940/1.244 ms`.

## Hands-on correction

The first owner browser launch exposed a scientific-route regression:
`WarpDamBreakStudio._config()` included gameplay-only `substeps`, projection,
velocity-damping, and XSPH keys for every mode, causing
`DamBreakConfig.from_mapping()` to reject Adaptive/Uniform before CUDA setup.
Configuration assembly now adds these fields only for Gameplay. The studio
test sends both Adaptive and Uniform payloads through the real
`DamBreakConfig.from_mapping` boundary, and the exact Adaptive spawned-worker
smoke passes on the RTX 5090 with pause/step/resume, two adaptation events,
2,080 final fluid particles, and finite state. Studio remains `21 passed`.
